## Build History

1. The inherited generated state failed in host `apk-3.0.5` because relocated
   Meson data still referenced the V6.85 staging path.
2. Initial clean-state removal exposed root-owned generated files. A guarded
   root purge removed only `build_dir`, `staging_dir`, `tmp`, `logs`, and `bin`
   from the exact overlay mount.
3. The first clean build was deliberately interrupted after confirming clean
   regeneration so console verbosity could be removed without discarding its
   full log.
4. The next full build reached `uboot-airoha` and failed because WSL imported a
   Windows PATH entry containing `Program Files (x86)` into an unquoted U-Boot
   package command.
5. A focused U-Boot retry was invoked without remounting the overlay and failed
   before compilation. This was a mount-namespace invocation error.
6. The final resume ran every build/source-controlled command with `env -i` and
   a Linux-only PATH. It passed and produced exactly one W1700K sysupgrade ITB.

and uses a whitespace-tolerant installed-asset marker.

## Boundaries

- This is an engineering/provenance candidate, not a release-authoritative
  promotion. The release certifier still records B-01/B-02/B-03 as open around
  WSL interop and sandboxing of source/image-controlled execution.
- Stock-parity NPU TX ledger/completion/reset/drain work represented by patches
  52 and 79 remains `BLOCKED-DESIGN`; this image does not claim it complete.
- V6.86 was flashed and live-tested. It exposed a hostapd MLO country-field
  alias bug and a 2.4 GHz EHT40 coexistence failure during tri-band MLO setup.
  Both were corrected in V6.87; V6.86 must not be reflashed.
- Ethernet identity and the changed SSH key were independently pinned to the
  W1700K before V6.86/V6.87 management. Global `known_hosts` was not weakened.

## Live Findings And Supersession

- V6.86 successfully booted and provided the clean source/build baseline used
  for corrective testing.
- MLO country validation read `config.country` after normalization had moved
  the value to `config.country_code`, causing false country mismatches.
- Tri-band MLO with radio0 at EHT40 encountered mandatory 20/40 coexistence
  fallback. This stack could not update the assembling MLD and failed beacon
  setup. Ordinary standalone 2.4 GHz EHT40 remained valid.
- The V6.87 corrective image requires EHT20 only for 2.4 GHz MLO members and
  accepts the normalized country field. It passed 38/38 installed-image tests.
