## Consumer Oracles

- TX `tx_oracle` and `tx_completed`, lines 199-254, predict SRAM stores,
  subregion-derived masked register values, and lookup returns from pre-call
  state. The supplied host value is not treated as a descriptor allocation.
  All completed calls compare the 786432-byte SRAM/heap/L2 images, unique
  non-stack memory write set, ordered register writes, and final register values.
- TXDONE `done_oracle`, lines 263-333, derives free-ID consumption, partial
  exhaustion, descriptor words, counters, occupied IDs, state, and rebuilt
  queue independently of observed stores. `done_completed`, lines 336-367,
  checks the full resulting images, exact unique write extent, allocation
  returns, mutex-write order, temporary-table read addresses, and final ready
  publication. Its oracle is not an exact ordered oracle for every RAM load
  and store. Access-stop controls at lines 472-498 check stop location and
  absent return/readiness, not a full partial-state oracle; TX report lines
  93-104 accurately preserve that distinction.
- TXBUF `oracle`, lines 203-243, predicts each ordered successful RAM store
  from the record ABI and pre-call tables, including failure prefixes and
  explicitly modeled external packet-base release. `read_oracle`, lines
  246-286, independently predicts non-stack load tuples and multiplicities.
  Checks at lines 289-363 retain descriptor tail bytes, unchanged host pools,
  exact write order/extent, exact non-stack read footprint/values, pointer
  publication order, and wrapper completion. Read multiplicity is checked;
  arbitrary global load-order equivalence is not claimed.
- TXBUF report totals of 53258 nominal RAM stores and 47 non-stack reads agree
  with the four receipt entries. The 1536 128-byte records and 1024 16-byte
  descriptors match the fixed counts and strides. The separate pending-label
  list is explicitly relative to its RX checkpoint, not concurrent-parent status.

TXDONE compares 856064 bytes; TXBUF compares 1048576 bytes. These are explicit
emulator regions, not all physical memory or proof of physical reservations.
Stack/transport storage is outside those full-image totals. Synthetic host
views do not establish alias/cache coherence. TXBUF's logical host capacity
can be zero while backing pages remain mapped; its callbacks make no pool
accesses, so successful return proves no host-capacity validation.

Focused runs checked all 14 selected TX native spans and all nine TXBUF spans
against pinned CODE. TXBUF includes the separately bounded 162-byte initializer
at `0x8400ee94..0x8400ef36`. The suites check full loaded native CODE identity
after each callback. These are selected native instruction identity checks,
not a new firmware build or fresh Ghidra analysis.

TX's observer subclass changes observation of later SKB-state stores, not
native instructions. Its callback allowances include printf and hart-ID
models; boot substitutions are separately listed. TXBUF keeps native lookup,
initializer, and delay bodies, with printf as its callback return substitution.
The delay's explicit post-CSR A5 input override is a model, not real timing
proof. Storage-only MMIO/mutex observations establish neither arbitration nor
DMA quiescence. The finite reached-entry allowlists do not prove all possible
control-flow paths in the firmware.

## Readiness And Remaining Limits

Native wrapper return 1 is not readiness: exhaustion can retain consumed IDs
with ready 0; malformed/zero counts can still publish ready; TXBUF publishes
pointers before initialization and lacks a dedicated ready publication. An
emulator memory/CSR stop is not native error propagation, rollback, or a
demonstrated client fault. No live token reclamation is authorized by these tests.

The full host message sequence, other workers, concurrency, physical timing,
DMA/cache/containment, loader, recovery/removal, hardware/client acceptance,
and stock parity remain unproved. The restricted page-callback lane was not
researched, executed, retried, or rerouted.

Only this `REVIEW.md` was written by the reviewer. No source, helper, firmware,
build, ELF, Git, hardware, network, router, flash, deletion, or other file-write
operation was performed. The reviewer left the ledger unchanged; parent-owned
report/ledger finalization is separate from this review.
